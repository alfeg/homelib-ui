MyHomeLib в Docker

Свой сервер библиотеки: поиск, OPDS-каталог для читалок и скачивание книг прямо из торрента, без загрузки всей коллекции.

Что понадобится

  • Docker с Compose v2 (docker compose version).
  • ~2 ГБ на диске под поисковый индекс, ~1 ГБ RAM во время первой индексации.
  • Магнет-ссылка на библиотеку с INPX-файлом (например, Флибуста).

Быстрый старт

Исходники не нужны — достаточно одного compose-файла, образ приложения скачается из GitHub Container Registry:

mkdir homelib && cd homelib
curl -fsSLO https://raw.githubusercontent.com/alfeg/homelib-ui/master/docker-compose.minimal.yml

LIBRARY_MAGNET_URI='magnet:?xt=urn:btih:...' \
  docker compose -f docker-compose.minimal.yml up -d

Откройте http://localhost:5080.

Поднимаются три контейнера: torrserve (работа с торрентом), meilisearch (поиск) и myhomelib (веб-приложение, образ ghcr.io/alfeg/homelib-ui). Наружу открыт только порт 5080.

Конкретная версия вместо latest: HOMELIB_TAG=1.2.3 или HOMELIB_TAG=sha-4d44417.

Чтобы не передавать ссылку каждый раз

Положите её в файл .env рядом с compose-файлом — Compose прочитает его сам:

LIBRARY_MAGNET_URI=magnet:?xt=urn:btih:...

Первый запуск

  1. Сервер скачивает через торрент только INPX (~35 МБ) — на «холодном» торренте это минута-две.
  2. Индексация ~700 000 книг в Meilisearch — около 5 минут. Пока она идёт, /m и /opds показывают прогресс и обновляются сами.
  3. При перезапуске индекс не строится заново, если коллекция не изменилась: готово за секунды.
docker compose -f docker-compose.minimal.yml logs -f myhomelib

Адреса

АдресДля чего
/Полное приложение для браузера
/mПростые страницы без JavaScript — для e-ink читалок. Читалки перенаправляются сюда сами

Настройки

Добавляются в environment сервиса myhomelib. Разделитель уровней — двойное подчёркивание.

ПеременнаяПо умолчаниюЧто делает
Library__TitleMyHomeLibНазвание библиотеки в /m и OPDS
Library__BlockedGenres__0, __1…—Коды жанров, скрытые в /m и OPDS (например, для детской читалки)
Torrent__DownloadsPerMinutePerClient10Скачиваний в минуту с одного IP, сверх — 429. 0 — без ограничения
Torrent__MaxConcurrentDownloads2Одновременных обращений к TorrServe
Library__ForceReindexfalseПерестроить индекс при старте

Поисковые боты на /download получают 403, а /robots.txt закрывает скачивание и API. Если сервер стоит за обратным прокси, все запросы приходят с одного IP — и лимит на клиента становится общим.

Обновление

docker compose -f docker-compose.minimal.yml pull
docker compose -f docker-compose.minimal.yml up -d

Индекс и данные TorrServe лежат в томах meili_data и torrserve_data и переживают пересборку.

Полный вариант

docker-compose.yml из репозитория — то же самое плюс ключ Meilisearch, ограничения памяти, healthcheck и тонкая настройка .NET. Настраивается через .env (образец — .env.example). Тоже берёт готовый образ; собрать из исходников:

git clone https://github.com/alfeg/homelib-ui.git && cd homelib-ui
GIT_SHA=$(git rev-parse HEAD) docker compose up -d --build

Если что-то не так

  • Долго нет прогресса — торрент без сидов. Смотрите logs -f torrserve.
  • Скачивание отвечает 503 — TorrServe занят другими скачиваниями; повторите через полминуты.
  • Скачивание отвечает 429 — превышен лимит в минуту для вашего IP.
  • Начать индекс с нуля: docker compose -f docker-compose.minimal.yml down -v удалит тома вместе с индексом.

РусскийMyHomeLib with Docker

Your own library server: search, an OPDS catalog for reader apps, and book downloads straight out of the torrent without fetching the whole collection.

You will need

  • Docker with Compose v2 (docker compose version).
  • ~2 GB of disk for the search index, ~1 GB of RAM during the first indexing run.
  • A magnet URI for a library that ships an INPX file (Flibusta, for example).

Quick start

No source checkout needed — one compose file, and the app image is pulled from GitHub Container Registry:

mkdir homelib && cd homelib
curl -fsSLO https://raw.githubusercontent.com/alfeg/homelib-ui/master/docker-compose.minimal.yml

LIBRARY_MAGNET_URI='magnet:?xt=urn:btih:...' \
  docker compose -f docker-compose.minimal.yml up -d

Open http://localhost:5080. Three containers start — torrserve, meilisearch and myhomelib (image ghcr.io/alfeg/homelib-ui) — and only port 5080 is exposed. Pin a version with HOMELIB_TAG=1.2.3 or HOMELIB_TAG=sha-4d44417.

To avoid passing the magnet every time, put LIBRARY_MAGNET_URI=... in a .env file next to the compose file.

First start

The server fetches only the INPX (~35 MB) through the torrent, then indexes ~700,000 books in about five minutes. Meanwhile /m and /opds show progress and refresh themselves. Restarts reuse the index when the collection has not changed.

Addresses

/ — the full browser app · /m — script-free pages for e-ink readers (readers are redirected there) · /opds — add http://<server>:5080/opds to your reader's network library · /api/status — indexing state as JSON.

Settings

Add them to the environment of the myhomelib service: Library__Title, Library__BlockedGenres__0…, Torrent__DownloadsPerMinutePerClient (default 10, 0 disables), Torrent__MaxConcurrentDownloads (default 2), Library__ForceReindex.

Crawlers on /download get 403, and /robots.txt disallows downloads and the API. Behind a reverse proxy every request arrives from one address, so the per-client limit becomes shared.

Updating

docker compose -f docker-compose.minimal.yml pull
docker compose -f docker-compose.minimal.yml up -d

The index and TorrServe state live in the meili_data and torrserve_data volumes and survive a rebuild. down -v deletes them to start from scratch.

Full setup

docker-compose.yml adds a Meilisearch key, memory caps, a healthcheck and .NET tuning, configured through .env (see .env.example). It pulls the same image; to build from source:

git clone https://github.com/alfeg/homelib-ui.git && cd homelib-ui
GIT_SHA=$(git rev-parse HEAD) docker compose up -d --build
